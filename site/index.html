Graphs that turn questions about building data into small, inspectable, reproducible computations, built the same way by people in a web editor and by AI agents over MCP (Model Context Protocol).

Status on 2026-10-03: the code is not in this repository yet. It lives in bim-open-toolkit under src/flow, bimopenflow/web, src/mcp/BimOpenMcp.Flow, and src/studio/BimOpenFlow.Ask, and its generic part moves here with its history in phase 5 of the repository split plan.

What a graph is

A graph is a JSON document of nodes and wires. Each node is a small function with typed ports and parameters edited on the node itself. A door schedule, rooms per storey, a check that every door leaf is at least 850 mm wide, or a 3D view coloured by category are each a graph of a handful of nodes.

load ──┬─► table.filter ──► table.aggregate ──┬─► chart.bar        (chart)
       │                                      └─► sink.exportCsv  (effect, waits for Run)
       └─► view3d.instances ──► view3d.color ────► 3D pane         (3D view)

Every edit is one of four operations, addNode, connect, setParam, and removeNode, whether it comes from a mouse gesture, the HTTP API, or an MCP tool. A graph an agent builds is one a person could have built.

What travels on a wire

Six kinds of value: Boolean, Integer, Number, Text, Table, and Relation. Almost everything is an immutable Table; a Relation is a query plan and its schema, which becomes rows only when executed. One vocabulary covers loading, SQL, table operations, charts, 3D, and rule checks, so a graph that computes a table can also colour the model.

Nothing writes until Run

Pure nodes only compute, and their results are memoized. Effect nodes write files or IFC property sets, all live in one pack, and stay EffectPending until an explicit Run. Exploring a model, by a person or an agent, never touches a file. Each node reports Ok, Unready, EffectPending, Unavailable, or Error.

Runs are the evidence

A run record pins the graph's hash and every input's content hash beside the outputs, and replays. A number an agent reports comes from a run or a tool result, not from memory. A run can be published as a self-contained HTML report or an evidence package: a zip whose manifest.json lists a SHA-256 per member.

What will arrive

  • The node packs: 124 node kinds in the toolkit's catalog on 2026-10-03, each declaring its ports, parameter kinds, and purity. The packs that know about buildings stay in the toolkit.
  • The headless host: graphs and runs on disk, and the four operations over HTTP.
  • The web editor: a canvas built on Gratify, tables and charts beside the graph, and an Ask box where an agent builds the graph from a question in plain language.
  • The MCP server, so an agent in Claude Code edits, evaluates, and reads graphs with the same operations.
  • The publishing projects: reports, dashboards, and evidence packages.

The engine itself, ara3d-dataflow, is specified separately with its own conformance suite and knows nothing about buildings.
